# v0.3 HUD prototype plan

## Trigger

Live acceptance of `v0.3.0-rc.1` showed no visible difference between the accepted `tagged` subtitles and the experimental localization-only `differentiated` HTML style.

That result invalidates the assumption that embedding `<font>` / `<i>` markup in the localization value is sufficient for visible styling in the retail Xbox/Microsoft Store 1.5.6 subtitle path.

## Decision

Do not iterate on localization-only styling.

The next prototype patches the effective retail `hud.gfx` at generation time, derived from the user's own game asset, and keeps the localization patch as data only.

## Minimal prototype architecture

1. Read `Data/IPL_GameData.pak` from the selected KCD2 `Content` root.
2. Extract exactly `Libs/UI/hud.gfx`.
3. Parse CFX/SWF enough to validate the expected retail subtitle anchors before modifying anything.
4. Inject a narrow AVM1 wrapper around `fc_setSubtitles` rather than rewriting the complete function:
   - preserve the original function under a project-owned name;
   - invoke the original function first;
   - only when the incoming subtitle contains the project marker, write the project's final HTML directly to `bc.subtitles.inside.tField.htmlText` after vanilla formatting has completed;
   - recompute the existing subtitle background afterwards;
   - non-project subtitles remain byte-for-byte/behaviorally vanilla.
5. Package the derived HUD into this mod's own data PAK as `Libs/UI/hud.gfx`; never modify `IPL_GameData.pak` or any original game file.

The first live prototype only needs to prove visible secondary styling. Runtime language lookup and in-game settings remain later v0.3 stages.

## Marker contract

The localization patch must use a versioned project marker that cannot plausibly occur in ordinary dialogue. The HUD wrapper recognizes only that marker, strips it from displayed text, and applies controlled markup. Unknown/malformed markers fall back to the original vanilla function output.

## Safety / compatibility

- Fail closed if `IPL_GameData.pak` is missing, malformed, lacks exactly one `Libs/UI/hud.gfx`, or the GFX semantic anchors are not recognized.
- Do not use one absolute byte offset as the compatibility check.
- Detect an existing foreign mod providing `Libs/UI/hud.gfx`; do not silently overwrite/compete with it. For the first prototype, report the conflict and stop rather than attempting a merge.
- Keep current `tagged` generation as the default stable path.
- HUD generation is explicit experimental opt-in until live acceptance.
- No proprietary GFX or localization assets are committed.

## CI acceptance

All automated acceptance remains GitHub Actions only.

Synthetic fixtures must prove:

- CFX decompression/recompression and SWF header validation;
- ZIP/PAK extraction of one exact HUD entry;
- malformed/missing/duplicate HUD entries fail closed;
- target AVM1 anchors are located structurally;
- missing/multiple/ambiguous subtitle targets fail closed;
- deterministic transformation;
- idempotent already-patched detection;
- unrelated SWF tags/actions are preserved;
- generated mod data PAK contains exactly the derived `Libs/UI/hud.gfx` path;
- default `tagged` path does not read or package `hud.gfx`;
- Linux tests, native Windows tests, Windows build, GUI smoke and CLI smoke remain green.

## Live acceptance

The next RC is successful only if the validated Xbox/Microsoft Store build visibly shows the secondary line with a clearly different color/style while preserving:

- ordinary NPC dialogue;
- cutscene/story dialogue;
- ambient/bark subtitles;
- speaker names;
- subtitle positioning/background;
- long wrapped lines;
- primary-only vanilla subtitles outside the project marker.

If this minimal wrapper fails, do not proceed to runtime language switching until the exact retail HUD execution behavior is re-investigated.
